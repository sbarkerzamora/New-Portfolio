# Impeccable — design context for AI assistants

Persisted context for design and UI work. **Update this file** when audience, brand, or visual direction changes.

## Design Context

### Users

- **Who**: Hiring managers, potential clients (SMBs and startups), collaborators, and technical peers evaluating Stephan Barker’s work.
- **Context**: Short, often mobile sessions—scanning credibility, opening the chat to probe experience, booking a call (Cal.com), or downloading the PDF CV.
- **Jobs to be done**: Quickly understand full-stack + digital-advisor positioning; validate stack and projects; move from curiosity to contact (email, booking, CV).

### Brand Personality

- **Three words**: *Clear*, *capable*, *grounded*.
- **Voice & tone**: Professional and direct; Spanish-first product copy with English support (`LanguageContext`). Aligns with profile values: transparency, steady communication, and pragmatic solutions—not hype.
- **Emotional goals**: Confidence in technical depth; calm, efficient UX; subtle delight via motion and background craft, not noise.

### Aesthetic Direction

- **Visual tone**: Dark-first immersive portfolio (glass headers, animated ColorBends background, refined typography). **Light theme is fully supported** in code (`ThemeContext`, `.light` tokens)—treat both as first-class; default HTML class is `dark`.
- **Typography**: Local **Neue Metana** for branded/display moments; **Geist Sans / Geist Mono** for UI and body (see `app/layout.tsx` and CSS variables).
- **Color system**: HSL tokens in `app/globals.css`—primary skews **violet** (~263°); dark surfaces are deep cool neutrals; light theme uses clean whites and restrained borders. Background accents shift with theme (e.g. green tones in dark ColorBends, softer purples in light).
- **Motion**: GSAP for orchestrated entrances; Motion and Three/postprocessing where used—motion should reinforce hierarchy and feedback; respect `prefers-reduced-motion` where implemented.
- **Stack expression**: shadcn/Radix primitives, Tailwind utilities, CSS Modules for feature layouts—prefer tokens and `cn()` over one-off magic values.
- **Anti-patterns (avoid)**: Generic “AI portfolio” look (neon-on-black clichés, interchangeable card grids, decorative noise without purpose). See `.cursor/skills/frontend-design/SKILL.md` for detailed “AI slop” checks.

### Accessibility & inclusion

- Semantic HTML and keyboard-friendly controls are expected for new work.
- **Formal WCAG conformance target** (e.g. AA vs AAA) is not defined in-repo—default to sensible contrast on both themes and visible focus states unless the owner specifies a level.

### Design principles

1. **Content over chrome** — The chat and profile data (`docs/profile.json`) are the hero; visuals support comprehension, not competition.
2. **Dual-theme parity** — New components and tokens must work in **dark and light** without breaking contrast or legibility.
3. **Motion with purpose** — Animate for orientation, feedback, and delight at key moments; avoid gratuitous layout thrash or blocking motion.
4. **Trust & clarity** — Copy and UI should feel honest and scannable; prefer explicit labels and status (e.g. connection state) over mystery meat navigation.
5. **Responsive by default** — Touch-friendly targets, safe areas, and readable type on small viewports; adapt layouts, don’t only shrink them.
